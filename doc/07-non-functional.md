# 非機能要件

[← 目次に戻る](README.md)

| 分類 | 内容 |
|---|---|
| 対応端末 | スマホ・PCの両方（レスポンシブ） |
| 対応ブラウザ | Chrome / Safari / Edge / Firefox の最新版 |
| 言語 | 日本語のみ |
| 認証方式 | ユーザー名＋パスワードの自前認証。誰でもサインアップ可能（詳細は [認証](03-auth.md)） |
| ログイン状態の保持 | 30日間。Cookie は `HttpOnly`・`Secure`・`SameSite=Lax` |
| パスワードの保護 | bcrypt でハッシュ化して保存し、平文は保存・ログ出力しない |
| 不正対策 | 誰でもサインアップできるため、総当たり攻撃（ブルートフォース）の対象アカウントが複数になる点に注意する。ログイン失敗回数の制限はサーバーレス環境での素朴な実装（メモリ上のカウンタ等）が効かないため今回は設けず、問題が出た場合はVercel側のレート制限等を検討する。通信はHTTPS（Vercel標準） |
| 表示速度 | 記事データはISR（`revalidate: 86400`）で保持し、Zenn APIへの問い合わせはキャッシュが古くなってアクセスがあったときだけ発生する |
| トピック切り替え時のサーバー負荷 | 既読・ブックマーク・お気に入りトピックはTanStack Queryがブラウザ側にキャッシュする。初回取得後は、トピックを何度切り替えても（`staleTime`内は）サーバー・DBへ再度アクセスしない。切り替え回数が多いユーザーが増えても、サーバー負荷がそれに比例して増えない（詳細は [フロントエンド・バックエンドの構成](10-structure.md#既読ブックマークをクライアント側で取得する理由設計の経緯)） |
| 外部APIへの配慮 | Zennへのアクセスは、各トピックのキャッシュが切れてアクセスがあったときのみ発生する（ユーザー数が増えても、同一トピックのキャッシュは共有されるため負荷はほぼ変わらない）。記事は必ずZennの元ページへリンクし、出典を明記する。`User-Agent`にアプリ名と連絡先（GitHubリポジトリ）を含める |
| 非公式であることの明記 | フッターに「本アプリはZenn公式とは関係ありません」と表示する。Zennのロゴやそれに似たマークは使わない |
| プライバシー | 個人の状態（お気に入りトピック・既読・ブックマーク）はDB（Vercel Postgres／Neon）にユーザーIDに紐づけて保存する。他のユーザーからは見えない。パスワードはハッシュ化して保存し、記事本文など以外の個人情報（メールアドレス等）は取得しない |
| ダークモード | 対応しない |
