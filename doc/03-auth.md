# 認証

[← 目次に戻る](README.md)

## 方針

- ユーザー名＋パスワードのみ。メール認証・OAuth（Google/GitHubログイン等）は使わない
- 誰でもサインアップできる（招待制・承認制にはしない）
- セッションは jose で発行した JWT を httpOnly Cookie に保存する自前方式（Auth.js 等は使わない。詳細は [技術スタック](09-tech-stack.md) の検討経緯を参照）

## サインアップ（`/signup`）

| 項目 | 仕様 |
|---|---|
| 入力 | ユーザー名、パスワード、パスワード（確認用） |
| ユーザー名の制約 | 3〜20文字、英数字と `_` のみ |
| パスワードの制約 | 8文字以上 |
| 重複チェック | ユーザー名が既に使われている場合は登録できない。「そのユーザー名は既に使われています」と表示 |
| パスワードの保存 | bcrypt でハッシュ化してDBに保存する（平文は保存しない） |
| 登録後 | 自動的にログイン状態にし、`/topics?welcome=1`（初回トピック設定）へ移動する |

## ログイン（`/login`）

| 項目 | 仕様 |
|---|---|
| 入力 | ユーザー名、パスワード |
| 照合 | DBのユーザー名で検索し、bcryptでパスワードハッシュを照合する |
| 失敗時 | 「ユーザー名またはパスワードが違います」と表示する（ユーザー名の存在有無は区別しない） |
| 成功時 | JWT を発行し、httpOnly Cookie にセットして `/` へ移動する |

## セッション（JWT）

| 項目 | 仕様 |
|---|---|
| 発行ライブラリ | `jose` |
| ペイロード | `{ sub: userId, username }` |
| 署名鍵 | 環境変数 `AUTH_SECRET`（ランダムな文字列） |
| Cookie | httpOnly・secure（本番）・sameSite=lax、有効期限30日 |
| 検証場所 | `proxy.ts`（Next.js Middleware、Edge runtime）。DBにはアクセスせず、JWTの署名と期限だけを見る |
| 検証方法 | `jose` の `jwtVerify(token, secretKey)` を使う。**独自の署名比較ロジックは書かない**（下記「注意」参照） |
| 未ログイン・検証失敗時 | `/login`・`/signup` 以外へのアクセスはすべて `/login` にリダイレクトする |

### 注意：旧版で見つかったバグ

旧版の実装では、改ざんされたトークンを `true`（有効）と誤判定するバグがテストで発覚した。原因は検証ロジックを自前で書いていたことにある。今回は `jose` の `jwtVerify` 呼び出しの成否（例外が出たら無効）だけで判定し、部分的な文字列比較などの自前ロジックを書かないことで同種のバグを防ぐ。`verifyAuthToken` の単体テストには、署名改ざん・期限切れの両方のケースを必ず含める。

## ログアウト

- `/api/logout` が Cookie を削除する
- ヘッダーのログアウトボタンから呼び出す

## ルート保護（`proxy.ts`）

- `/login`・`/signup`・静的アセット以外のすべてのパスを保護する
- 未ログイン、または JWT が無効（署名不一致・期限切れ）の場合は `/login` にリダイレクトする
- DBへの問い合わせは行わない（JWTの検証のみ）。ユーザーIDが必要なページ（`/`、`/topics`、`/topics/[slug]` など）は、各 Server Component 内で Cookie から再度 JWT をデコードしてユーザーIDを取得する
