# 概要・技術構成

[← 目次に戻る](README.md)

## アプリの目的

Zenn の記事を、自分がお気に入りに登録したトピックごとに「最新順」で読める、パーソナルなニュースアプリ。

- **誰でもサインアップして使える**（ハッカソンでの公開・デモを想定）
- ユーザーごとに「お気に入りトピック」「既読」「ブックマーク」を管理する。他人のデータは見えない

旧版（`~/Desktop/ZennNews`）は開発者本人1人だけが使う前提で、アカウントは環境変数で固定、個人データはすべてブラウザの localStorage に保存していた。今回はこれを作り直し、不特定多数のユーザーが自分のアカウントを作って使える構成にする。

## コンセプト

Zenn には1日に数百件の記事が投稿されており、すべてを読むことはできない。
このアプリは「全部読む」ためではなく、**自分に関係のあるトピックだけを、自分のペースで追う**ためのもの。NEW はニュースアプリの見出しのように眺め、気になった記事だけを読む・ブックマークする、という使い方を想定する。

## スコープ

| 対象 | 内容 |
|---|---|
| 今回作る | ユーザー登録・ログイン（ユーザー名＋パスワード）、トピック別の最新記事表示、既読管理、ブックマーク（すべてDBでユーザーごとに管理） |
| 今回作らない | パスワードリセット・メール認証・OAuth連携、記事の分析機能、検索、ダークモード、特定ユーザーの新着を追う機能、管理画面 |

## 技術構成

主要な技術の一覧。詳細は [技術スタック詳細](09-tech-stack.md) を参照。

| 領域 | 技術 |
|---|---|
| フロントエンド | Next.js（TypeScript、App Router） |
| バックエンド | Next.js の Server Component / Route Handler（専用サーバーは別途立てない） |
| 認証 | 自前のユーザー名＋パスワード認証。bcrypt でハッシュ化し、jose で発行した JWT を httpOnly Cookie に保存 |
| DB | Vercel Postgres（Neon）。Drizzle ORM 経由でアクセス |
| 個人状態の保存 | DB（users / bookmarks / read_articles テーブル）。ユーザーごとに分離 |
| 個人状態の取得（クライアント） | TanStack Query が `/api/me/**` を呼び、既読・ブックマーク・お気に入りトピックを取得・キャッシュする |
| 記事データの取得・更新 | Zenn 非公式 API を Server Component から直接 `fetch`。ページ全体を Next.js の ISR（`revalidate`）でキャッシュする（全ユーザー共通のHTML） |
| 本番環境 | Vercel |
| CI/CD | GitHub Actions ＋ Vercel の自動デプロイ |
| データ取得元 | Zenn 非公式 API |

## 旧版からの主な変更点

| 項目 | 旧版 | 今回 |
|---|---|---|
| アカウント | 1組だけ（環境変数で固定） | 誰でもサインアップ可能（ユーザー名＋パスワード） |
| 個人データの保存先 | ブラウザの localStorage | DB（Vercel Postgres／Neon） |
| 既読・ブックマークの反映 | クライアント側で記事一覧とlocalStorageを合成（一瞬チラつく） | DBに保存し、クライアントがTanStack Queryで取得・キャッシュして記事一覧に重ねる（表示直後は一瞬チラつく可能性があるが、トピック切り替え時はキャッシュがあれば再取得しない） |
| 対象ユーザー | 開発者本人のみ | 不特定多数（ハッカソンでの公開を想定） |
